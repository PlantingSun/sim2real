# 19.5：深度有效区域与现场质量记录

本页记录 guide 19 之后的深度质量判断，不把“画面能显示”直接等同于“可以安全驱动策略”。

## 当前事实

当前 USB2 采集使用 `480×270 Z16 @60 FPS`。目标投影为 58°×58°、64×64。
D435i 标定光心不在图像几何中心，旧实现把轻微越界的最底部一行直接标成：

```text
valid = 0
depth_m = 2.0 m
```

2026-09-08 已改为从最近的真实传感器边缘行取值，前 63 行映射不变，底行不再固定无效。
采样使用最近邻，不混合前景和背景；源相机本身为 0 的位置仍为 `valid=0`。
其他缺测像素使用相同协议约定。`valid=1` 的真实远处像素也可能是 `2 m`，所以不能只看
深度灰度图判断有效性，必须同时看 `valid`。

## 为什么不把无效区域填成近障碍

直接把无效像素改成 0 m 会制造训练中不存在的近距离障碍，可能使 WMP 输出突然变化；插值或
复制邻近像素又会改变已确认的 simulation 输入语义。当前安全处理是：

1. 保持发布协议的 2 m 远平面和独立 `valid`；
2. 保留有效率和 valid mask 作为诊断，不因为无效比例变大而停止策略；无效像素继续按 2 m 远平面进入网络；
3. 不把 `valid` 擅自拼成网络的额外输入通道；
4. 底行边界修正只解决旧实现的人为无效行，不负责填补 D435i 原生缝隙。

当前 Go2WWMP 验证入口不再使用 `min_valid_ratio` 作为运行门槛。底行修正后有效率主要取决于相机
原生缺测；`valid_ratio` 仍写入日志，用于分析视野盲区、反光、缝隙和传输异常。深度过期、session
改变、畸形包和 NaN/Inf 仍是独立的数据链路故障，不能用无效像素处理掩盖。

## 现场记录

2026-09-08 底行修正实测：旧样本底行 `0/64` 有效且整行固定为 2 m；新样本底行
`64/64` 有效，米制范围约 0.279–0.286 m，倒数第二行仍保持自己的采样值。5 秒接收
300 张新帧，59.89 Hz，无缺帧、重复、逆序或畸形消息。该结果只说明本次场景的底部
源像素都有效；以后若相机原始边缘像素为零，对应输出仍会正确标为无效。

每次现场验收保留：

- `receiver.jsonl`、`summary.json`、`last_frames.npz`；
- `valid_ratio`、`invalid_pixels`、`depth_local_age_ms`、`depth_source_processing_ms`；
- 相机序列号、USB 模式、发布 session、网卡、网线拓扑和安装位置；
- 一张同时显示米制图和 valid mask 的 PNG。

## 两分钟真实环境录制

为了决定是否需要连通域或邻域处理，先在笔记本上做只读录制。抱着机器人在实际环境中缓慢
转动/走动一圈，覆盖缝隙、圆柱、反光和不同距离；不要启动任何 LowCmd 或 action：

```bash
python scripts/depth/record_scene.py \
  --duration 120 \
  --output logs/depth/scene_walk_20260908.npz
```

输出同时生成同名 `.json` 摘要。NPZ 保留每一帧 `depth_m`、`valid`、session/frame、发送/接收
时间戳和每帧有效率；不要只保存一张最终图。录制结束后再做离线分析，重点查看：

- 无效区域是否固定在图像边缘，还是随物体/视角移动；
- 无效连通块的面积、形状和跨帧持续时间；
- 无效块边界附近的真实深度分布，是否存在明显的大障碍表面；
- 录制期间 frame gap、session 和接收频率是否正常。

在这些证据出来前，不自动把无效块复制邻值、插值或按邻域改成近距离障碍。

可直接生成连通块、跨帧持久性和无效块邻域深度统计：

```bash
python scripts/depth/analyze_recording.py \
  logs/depth/scene_walk_20260908.npz \
  --output-image logs/depth/scene_walk_20260908_invalid_frequency.png
```

该分析只读原始录制，不会生成控制输入；`*_analysis.json` 中的邻域深度统计只用于讨论，
不能直接当作填补规则。

## 本地可视化回放

无需连接相机或机器人，可以直接回放三联图（米制深度、valid mask、WMP 输入）：

```bash
python scripts/depth/replay_recording.py \
  logs/depth/scene_walk_20260908.npz \
  --speed 1 \
  --max-gap-ms 1000
```

窗口中按空格暂停/继续，按 `q` 或 `Esc` 退出。默认把超过 1 秒的录制空档压缩为 1 秒；如果要
按原始时间保留本次约 51 秒空档，可将 `--max-gap-ms` 改为 `60000`。

需要进一步降低风险时，按以下顺序处理：

1. 先确认无效区域是固定几何边缘还是随机缺测；
2. 再检查 USB3/线缆和相机固定，重新生成 64×64 样本；
3. 用已冻结的 simulation 投影参数复核方向、距离和有效率；
4. 最后才讨论改变视场、滤波或训练输入。未经重新对齐，不在接收代码中偷偷改写图像。

## 与 MuJoCo 的比较和 OOD 结论

当前已对齐的是可直接验证的接口语义：64×64、58°×58°、光轴 Z 深度、0–2 m、图像方向，
以及 WMP 的 `clip(depth,0,2)/2-0.5` 后处理。MuJoCo/训练配置的 `dis_noise=0.0`，渲染图
没有 RealSense 立体匹配产生的随机缺测、缝隙、飞点和材质相关噪声。

目前没有采集“同一几何场景、同一相机外参”的 MuJoCo 与 D435i 配对数据，因此不能量化边界误差，
也不能证明输入不会 OOD。`scene_walk_20260908` 中有效率约 `0.74–1.0`、中位数约 `0.927`，
已经说明真实图与无噪声仿真图存在明显分布差异。底行修正消除了一处人为 OOD，但不会消除相机
原生无效区域。

本阶段按用户要求不在 Orin 填补这些缝隙。后续应在笔记本端保留原始 `depth_m + valid`，
分别比较填补前后有效率、连续帧抖动和障碍边界，再决定接收端处理或重新训练/域随机化。

下一步真机验证入口和固定站姿流程见 [guide 20](20_go2wwmp_real_validation.md)。
