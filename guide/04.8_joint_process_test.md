# Step 4.8：policy + DDS 联合进程测试

本阶段将在 4.6、4.7 分别通过后进行。policy 进程和 DDS/LowCmd 进程通过轻量状态/命令
通道交换数据，DDS 进程持续发布最新有效动作。先运行 `print-only`，确认频率、延时和
进程退出清理都正常，再进入 Step 5。

机器人吊起并确认 4.7 已通过后，先运行 print-only 联合测试：

```bash
python scripts/real/test_policy_multiprocess.py \
  --release --print-only --duration 30 \
  --policy-cpus 2 --lowcmd-cpu 1 --torch-threads 1
```

主进程负责 DDS/LowCmd，子进程负责 policy；`--print-only` 时 policy action 不会发送。
默认按训练频率 50 Hz 运行。确认 `[RATE] joint policy` 稳定后，去掉 `--print-only` 才会
发送 policy action。若只测量双进程最大吞吐率，可显式加 `--rate 0`，但不能用该模式
直接运行按 50 Hz 训练的网络。退出时两个进程都会关闭，主进程进入紧急阻尼。

默认前 3 秒为 policy 预热：子进程继续接收状态、填充历史观测并计算 action，但主进程
仍保持固定 `INITIAL_JOINTS_POS`，预热结束后才允许 policy action 接管。可用 `--warmup`
调整预热时间。

4.8 已验证：print-only 和实际 policy 接管均能在轻微扰动下保持明显优于原单进程版本的
表现。该架构现已迁移到 `scripts/real/test_policy_real.py`；本文件保留联合测试说明。
