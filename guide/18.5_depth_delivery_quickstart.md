# 18.5：机载深度服务交付摘要

本页只说明 Orin 端深度服务的当前交付状态和现场检查。它不运行策略，不发布 LowCmd，
也不调用 Sport Mode。

## 当前链路

```text
D435i → Orin 采集/空间滤波/58°重采样 → 64×64 米制深度 + valid → DDS domain 42
```

固定接口：

- 深度 domain：`42`；topic：`rt/depth/image64`；类型：`go2w_depth::DepthFrame` v1；
- QoS：BEST_EFFORT、KEEP_LAST(1)、VOLATILE；
- 深度：`float32 (64,64)`，米制光轴 Z 深度，范围 `[0,2]`；
- 无效值：`valid=0` 且深度填 `2 m`；
- 当前 USB2 模式：`480×270 Z16 @60 FPS`；标定光心偏移造成的底行轻微越界已改为最近传感器边缘采样；
- DDS 分片：`MaxMessageSize=1400B`、`FragmentSize=1280B`。

## 服务检查

在 Orin 上：

```bash
systemctl is-enabled go2w-depth.service
systemctl status go2w-depth.service --no-pager
journalctl -u go2w-depth.service -n 30 --no-pager
```

日志必须同时出现 `CONNECTED` 和持续更新的 `STATS`。只有 `active/running` 而没有新帧统计，
不能视为相机链路正常。

服务启动失败时，先检查相机是否被 `realsense-viewer` 或其他采集进程占用。不要同时启动两个
正式发布者；模拟发布必须使用独立测试 domain。

## 当前已知限制

- 当前设备实际协商为 USB2，不应把 USB3 的分辨率/视场假设写入控制代码；
- 底部一行不再人为标成无效；相机原生无效点仍通过 `valid=0` 原样标出；
- 机载端只发布米制深度，不执行 WMP 的 `[-0.5,0.5]` 归一化；
- 深度服务和电机 domain 0 隔离。最终实机可以同时运行 domain 0 电机进程和 domain 42 深度进程。
