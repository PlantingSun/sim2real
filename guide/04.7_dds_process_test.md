# Step 4.7：独立 DDS/LowCmd 进程测试

本阶段将在 4.6 通过后进行：DDS 进程独立接收 LowState 并维持 500 Hz LowCmd，先使用
固定站姿，不接收或发送 policy action。测试目标是确认 DDS 进程自身的发布频率和 CPU
占用，不修改现有 `5_real_test`。

机器人吊起并确认周围安全后运行：

```bash
python scripts/real/test_dds_process.py \
  --lowcmd-cpu 1 --duration 30 --release
```

当前脚本不接受日志参数；频率直接打印到终端。`--release` 只在确认当前可以释放
Sport Mode 时使用；若已经手动释放，则省略该参数。退出时脚本会进入紧急阻尼。

通过标准：`[DDS RATE]` 接近 500 Hz，且运行期间没有异常抖动。若频率明显低于 500 Hz，
先不进入 4.8，继续检查 LowCmd 线程和 CPU 调度。
